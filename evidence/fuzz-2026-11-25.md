# Fuzz runs, 2026-11-25

cargo-fuzz 0.13.2, nightly toolchain, libFuzzer with sanitizers, 1 vCPU. Single runs on one machine. No crashes, panics or sanitizer errors in any run. This shows only that these inputs did not break the parsers in this time. It is not a security result.

| target | what it feeds | time | executions | coverage (cov/ft) |
| --- | --- | --- | --- | --- |
| decrypt | arbitrary key + envelope into open() | 36 s | 2,352,727 | 855 / 1134 |
| parse | existing parser target | 36 s | 943,602 | 1218 / 2777 |
| hybrid (new) | random or exact-length KEM public key, X-Wing ciphertext, sealed message, verifying key, signature | 61 s | 91,638 | 1398 / 1949 |

A first hybrid run (22 million executions in 91 s) reached only 45 coverage points because almost every input failed the length check. The target was changed to resize half the inputs to the exact valid length; the table shows the run after that change. Reproduce: `cd fuzz && cargo +nightly fuzz run hybrid -- -max_total_time=60 -max_len=5000`.

## Longer hybrid run (same day)

Background jobs do not survive in this sandbox, so the run was four consecutive foreground sessions of 100 to 106 s on the same growing corpus: 89,243 + 98,583 + 95,777 + 94,842 executions (378,445 in about 7 minutes), plus the 91,638 above. Coverage stayed at 1398 points in every session, so this target is saturated at this input shape. No crash, panic or sanitizer error; fuzz/artifacts has no crash files. About 8 minutes total is still a smoke test, not a campaign.
